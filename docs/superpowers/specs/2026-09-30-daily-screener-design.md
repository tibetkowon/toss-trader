# 일일 종목 스크리너 설계 (SPEC.md 3.3 개정안)

상태: 초안 v2, 사용자 리뷰 대기. 승인되면 SPEC.md 3.3/11절에 반영하고 구현 계획으로 넘어간다.

## 1. 목적과 결정 사항

고정 8종목 워치리스트를 폐기하고, 매일 종목을 새로 구성한다. 국장·미장에 같은 로직을 쓴다.

사용자가 정한 것:
- 종목은 매일 바뀌어야 한다. 매일 같은 종목만 보는 것은 이상하다.
- API 호출은 429가 나지 않는 범위에서만 쓴다.
- 당일 실시간 랭킹을 쓴다. 장 시작 후 어느 정도 방향이 잡힌 종목을 대상으로 한다.
- 후보는 아침에 고정하지 않는다. 장중에 뜬 종목도 잡을 수 있어야 한다.
- 활성(감시·진입) 종목은 10개.
- 구성 요소가 과하거나 효과가 없으면 검증 후 제거한다.

이번 범위 밖: 미장 세션 복구(통합 잔고, 소수점 주문, 환율)는 별도 설계. 스크리너는 시장 무관하게 설계한다.

## 2. 진단으로 확인한 사실 (2026-09-30, VM에서 실 API)

**당일 랭킹은 장중 실시간 값이다.** 12:17 KST에 `Rankings(MARKET_TRADING_AMOUNT, 1d, KR)`의 `tradingVolume`이 같은 시각 일봉 `candles[0]`(형성 중인 오늘 봉)의 거래량과 몇 초 차이로 일치했다(예: 000660 2,107,104 vs 2,109,145). 상위에 전일 대비 +24.45% 종목(266690)이 7위로 있었다. `1mo` 랭킹은 100위 안의 구성이 거의 바뀌지 않는다.

**돌파는 개장 직후에 몰리지 않는다.** 기존 8종목, 직전 25거래일, 정상 목표가 기준, 1분봉 고가로 첫 돌파 시각을 측정했다(200 종목·일 중 돌파 77건, 미돌파 123건).

| 돌파 시각(개장 후) | 건수 | 비율 |
|---|---|---|
| 0~5분 | 17 | 22% |
| 5~10분 | 7 | 9% |
| 10~30분 | 7 | 9% |
| 30~60분 | 15 | 19% |
| 60분 이후 | 31 | 40% |

5분 지연 시 잃는 신호 22%, 30분 지연 시 40%. 추세 필터(MA5)를 통과한 92건만 봐도 모양은 같다. 고가 기준이라 초반 비중은 약간 과대평가되어 있다. 표본이 8종목 × 25일이라 시작 지연은 설정값으로 두고 백테스트로 다시 확인한다.

## 3. 구조

후보 목록을 아침에 고정하지 않는다. 종목 평가(필터·목표가 계산)는 그 종목이 언제 등장하든 어제까지 확정된 데이터로 할 수 있으므로, 처음 보는 종목은 그때 평가하고 하루 동안 캐시한다.

**평가 (`Evaluate(symbol)`)** — 종목 하나에 대해 어제까지 데이터로 판정하고 결과(통과 여부, 탈락 사유, 목표가, 추세 결과)를 그날 캐시한다. 탈락도 기억해서 다시 조회하지 않는다.
1. 종목 속성: `Stocks`로 레버리지/인버스(`leverageFactor`가 없거나 1이 아님), 정리매매, 거래정지 제외.
2. 노이즈: 직전 20일 평균 (고가 - 저가) / 시가가 `NOISE_MIN`~`NOISE_MAX` 구간(초기값 2.5~6%)일 것.
3. 유의사항: 2까지 통과한 종목에만 `StockWarnings` 조회, 비어 있지 않으면 제외.
4. 오늘의 `Setup`: 일봉으로 목표가·추세 필터 계산. 오늘 시가는 정규장 첫 1분봉에서 가져온다(개장 후에만 확정).
5. 시드로 살 수 있는 종목이 활성 집합에 최소 2개 있도록 한다(SPEC 3.3 기존 규칙 유지).

**아침 사전 평가 (장 시작 전)**: 어제 마감 기준 `Rankings(1d)` 상위 종목을 미리 평가해 개장 직후 대부분 캐시에 있게 한다. 시가 기반 목표가는 개장 후 확정되므로, 사전 평가에서는 1~3만 하고 4는 개장 후에 한다.

**장중 루프 (개장 후 `RANK_START_DELAY` 분 뒤부터, `RANK_REFRESH`마다)**
1. `Rankings(1d)` 상위 `RANK_DEPTH`(초기 30)개를 조회한다(호출 1건).
2. 캐시에 없는 종목은 평가한다. 신규 평가는 분당 `EVAL_PER_MIN`(초기 3)개로 제한한다.
3. 평가를 통과한 종목 중 당일 랭킹 상위 `ACTIVE_COUNT`(10)개가 활성 종목이다.
4. 폴링과 진입은 활성 종목에만 한다. 밀려난 종목은 폴링을 멈춘다. 이미 진입한 포지션은 랭킹과 무관하게 손절·강제청산 규칙을 따른다.
5. 랭킹 조회가 실패하면 직전 활성 집합을 유지한다. 한 번도 성공하지 못했으면 사전 평가를 통과한 종목의 전일 거래대금 순 상위 10개를 쓴다.
6. 동시 돌파 시 우선순위는 SPEC 4.2대로 먼저 감지한 종목, 동시면 당일 랭킹 상위 종목.

**갱신 주기 `RANK_REFRESH`(기본 60초)**: 활성 10개를 다시 뽑는 간격이다. 짧으면 장중에 떠오른 종목을 바로 잡지만 10위 언저리 종목의 순위 진동이 생기고, 길면 안정적이지만 새로 뜬 종목의 편입이 늦어 추격 상한에 걸린다. 진동이 문제로 보이면 히스테리시스(`ACTIVE_KEEP_RANK`: 한 번 활성이 되면 순위가 이 값 밖으로 밀릴 때까지 유지, 초기 20)를 켠다.

**추격 상한 `CHASE_LIMIT_PCT`(초기 1%)**: 현재가가 목표가를 이 비율 넘게 넘어서 있으면 그날 그 종목은 진입하지 않는다. 지연 후·신규 편입 후 첫 틱에 이미 오른 종목을 쫓아 사지 않게 한다.

**구조적 한계**: 이 전략은 목표가를 넘기 **전에** 그 종목을 이미 보고 있어야 산다. 아침부터 급등해서 순위에 오른 종목은 목표가를 이미 크게 넘어서 추격 상한에 걸린다. 장중 확장이 효과를 내는 경우는 거래대금이 붙어 순위가 오르는 중이고 아직 목표가 아래에 있는 종목이 이후 돌파할 때다. 이런 경우가 얼마나 있는지는 백테스트로 확인한다.

## 4. 호출량 예산 (429 방지)

`tossapi.Client`는 그룹별 `X-RateLimit-*` 헤더로 한도에 걸리면 `BlockedUntil`까지 자동 대기한다. 아래는 호출 수 자체를 작게 유지하는 계획이다.

| 시점 | 호출 | 수량 |
|---|---|---|
| 아침 사전 평가 | 랭킹 1, stocks 배치 1, 종목별 일봉 1 + 유의사항 1(노이즈 통과 시) | 종목당 최대 2건 |
| 장중 | 랭킹 | 분당 1 |
| | 신규 종목 평가(일봉, 시가용 1분봉, 종목 정보, 유의사항) | 종목당 약 4건, 분당 최대 3종목 |
| | 활성 종목 시세 | 4초마다 최대 10건 |

하루 총 평가 호출은 "그날 랭킹 상위 `RANK_DEPTH`에 한 번이라도 든 종목 수"로 제한된다. 캐시된 종목은 다시 조회하지 않는다. 아침 사전 평가는 장 시작 전에 끝나야 하므로 상한 시간을 두고, 초과하면 평가를 마친 종목만 캐시에 남기고 로그로 남긴다.

## 5. 구성 요소

- **`internal/screener`** (신규, 시장 무관)
  - `Source` 인터페이스: `Rankings`, `Stocks`, `StockWarnings`, 일봉·1분봉 조회. 테스트에서는 가짜 구현을 쓴다.
  - `Evaluator`: 종목 평가와 하루 캐시.
  - `Gate`: 랭킹 스냅샷과 평가 결과로 활성 집합을 계산하는 순수 함수(히스테리시스 포함)와, 주기 조회 러너.
- **`internal/strategy`**: `Watchlist` 변수 삭제. `Setup`/`SplitBars`/`TargetPrice`는 그대로 쓴다.
- **`internal/session`**: (date, market)별 평가 캐시(종목, 통과 여부, 탈락 사유, 목표가, 추세 결과)를 저장하고 복구한다. 장중 재시작 시 다시 평가하지 않고 저장된 캐시를 쓴다. 활성 집합은 매분 다시 계산하므로 저장하지 않는다.
- **`cmd/trader`**: `pollWatchlist`/`todaySetups`가 고정 리스트 대신 게이트의 활성 집합을 쓴다. 시장 인자를 받는다.
- **`cmd/backtest`**: 6절 방식으로 같은 `screener`를 쓴다.
- **`internal/snapshot`**: 대시보드에 활성 종목, 평가 통과·탈락과 사유를 보여준다.

## 6. 백테스트

랭킹 API는 과거 순위를 주지 않으므로 재구성한다.

- 표본: 오늘 기준 `1mo` 랭킹 상위 100개를 과거 구간의 종목 모집단으로 쓴다. **생존편향이 있다**(지금 활발한 종목만 표본에 있다). 결과는 근사치로 해석한다.
- 종목 평가: 각 과거일에 전일까지의 일봉만으로 같은 규칙을 적용한다. 유의사항은 과거 시점 값을 알 수 없어 현재 값을 쓴다.
- 장중 랭킹: 1분봉의 누적 `종가 × 거래량`으로 분 단위 순위를 재구성해 같은 `Gate`에 넣는다.
- 1분봉 조회는 429가 잘 나므로 종목당 구간을 나눠 조회하고 로컬 파일에 캐시한다.
- **비교 실험**(같은 표본):
  - 게이트 끔 / 켬
  - 시작 지연 0 / 5 / 10 / 30분
  - 후보: 아침 고정 / 장중 확장
  - 갱신 주기: 1분 / 1시간 / 1회
  - 히스테리시스 끔 / 켬
  - 효과가 없거나 오히려 나쁜 요소는 제거한다.
- **과최적화 방지**: 조정 대상 값(노이즈 구간, 시작 지연, 추격 상한, 갱신 주기)은 백테스트 구간의 앞부분에서 조정하고 뒷부분으로 검증한다. 조정하는 값의 수를 늘리지 않는다.

## 7. 검증 계획

- 백테스트는 구성 요소를 남길지 제거할지 정하는 곳이다.
- 페이퍼 트레이딩은 그렇게 정한 설정을 **고정**하고 실제 환경(API 지연, 재시작 복구, 체결 타이밍, 호출량)에서 동작을 확인하는 곳이다. 4주는 거래일 약 20일이라 요소별 성과를 가르기에는 표본이 부족하므로, 페이퍼 중 설정을 바꾸면 시계를 다시 시작한다.
- 4주 시계는 스크리너 설정이 확정된 뒤 실제로 처음 돈 날을 1일차로 잡는다. 9/28~9/30은 전략 버그가 있던 날이므로 검증 기간에서 제외하고 SPEC 11절에 기록한다.
- 각 요소(게이트, 장중 확장, 추격 상한, 시작 지연)는 설정으로 켜고 끌 수 있어야 한다.
- 로그·세션 DB에 남길 것: 매일 평가된 종목과 탈락 사유, 활성 집합 변화, 각 진입이 아침 사전 평가 종목인지 장중 신규 종목인지, 추격 상한에 걸려 놓친 신호. 페이퍼 중에도 각 요소가 기여했는지 사후에 볼 수 있어야 한다.

## 8. 테스트

- `Evaluator`: 가짜 `Source`로 각 필터(레버리지, 노이즈 구간, 유의사항, 최소 2종목 규칙), 탈락 결과 캐시, 신규 평가 분당 제한, 상한 시간 초과 시 부분 캐시.
- `Gate`: 랭킹 스냅샷 시퀀스에 대한 활성 집합 변화, 히스테리시스, 조회 실패 시 직전 집합 유지, 지연 전 진입 금지.
- 추격 상한: 목표가를 넘어선 정도에 따른 진입 허용/거부.
- 세션 복구: 장중 재시작 후 같은 평가 캐시가 복구되고 다시 조회하지 않는지.
- 백테스트: 종목 평가가 미래 데이터를 쓰지 않는지(전일까지의 일봉만 입력했을 때와 동일한 결과).

## 9. 초기 설정값 (백테스트로 조정)

| 항목 | 초기값 | 근거 |
|---|---|---|
| 랭킹 조회 깊이 `RANK_DEPTH` | 30 | 호출량 예산 |
| 활성 종목 수 `ACTIVE_COUNT` | 10 | 사용자 결정 |
| 노이즈 구간 | 2.5~6% | 기존 8종목의 구간, 백테스트로 조정 |
| 시작 지연 `RANK_START_DELAY` | 5분 | 진단: 신호 약 78% 유지 |
| 갱신 주기 `RANK_REFRESH` | 60초 | 호출량은 무관, 편입 지연 최소화 |
| 히스테리시스 `ACTIVE_KEEP_RANK` | 끔(켜면 20) | 진동이 관찰되면 |
| 추격 상한 | 1% | 임의값, 백테스트로 조정 |
| 분당 신규 평가 `EVAL_PER_MIN` | 3 | 429 방지 |

## 10. 알려진 한계

- 백테스트는 생존편향이 있어 실제 성과의 상한에 가까운 근사치일 가능성이 높다.
- 장중에 급등한 종목은 이 전략 구조상 추격 상한에 걸려 못 사는 경우가 많다.
- 10만원 시드에서는 선정된 종목 중 살 수 있는 종목이 적은 날이 있다. 최소 2종목 규칙으로 완화할 뿐 없애지는 못한다.
