# 스크리너 백테스트 설계 (SPEC v17 1단계)

목적: 지금 라이브로 도는 전략(일별 스크리너 + 변동성 돌파 + 추격 상한 + -2% 손절 + 마감 전 청산)을 과거 데이터로
다시 돌려, 설정(손절폭, 익절 방식, 개장 직후 진입 금지, KR 우선 규칙, 노이즈 구간)을 확정한다. 사전 부검
(SPEC 11절)에서 확인한 대로 현재 전략은 어떤 백테스트로도 검증된 적이 없다.

## 원칙

1. **라이브 코드를 그대로 재사용한다.** `internal/screener`(Gate, Evaluator, SelectActive), `internal/tradingloop`
   (ProcessTick, ChaseGuard), `internal/simulator`, `internal/strategy`를 쓰고, 백테스트용으로 로직을 복제하지 않는다.
   과거 데이터를 내주는 가짜 `screener.Source`를 만들어 Gate/Evaluator에 넣는다.
2. **미래 데이터를 쓰지 않는다.** 가짜 Source는 시뮬레이션 시계(`clock`) 이후의 데이터를 절대 돌려주지 않는다.
   `Candles("1d")`는 clock 날짜 이전 일봉(+당일 형성 중인 봉은 주지 않음), `Candles("1m", before)`는 clock 이전 분봉만.
3. **비용은 보수적으로.** 한국 증권거래세, 스프레드/슬리피지, 시장별 수수료를 시나리오로 반영한다.
4. **라이브와 대조 가능해야 한다.** 2026-10-01~10-09 구간을 재생해 실제 페이퍼 거래 11건과 비교한다.
5. 라이브 동작은 바꾸지 않는다(SPEC 10절 설정 동결). 시뮬레이터에 추가하는 필드는 0값이 기존 동작과 같아야 한다.

## 데이터

- 유니버스: `Rankings(MARKET_TRADING_AMOUNT, 1mo, KR|US)` 상위 100개를 **오늘 시점**에 한 번 받는다(생존편향, 문서화).
- 일봉: 종목별 `Candles(1d, 200)`. 거래량 필드 있음. 이 값으로 날짜별 사전 랭킹(전일 거래대금 = 거래량 × (O+H+L+C)/4)을 재구성한다.
- 분봉: 종목별 `Candles(1m, 200, before)`를 `before` 토큰으로 거슬러 올라가며 수집(호출당 200개, 초당 약 10회).
  국장은 NXT 장전/장후 봉이 섞여 있으므로 정규장(09:00~15:30 KST)만 쓴다. 미장은 정규장(09:30~16:00 America/New_York)만 쓴다.
  구간: 가능한 만큼(국장은 4월 말, 미장은 7월 중순까지 확인됨).
- 종목 정보(`Stocks`), 유의사항(`StockWarnings`): 종목당 한 번 현재 값을 받아 캐시한다. 과거 시점 값을 알 수 없다는 한계를 문서화.
- 캐시: `.cache/backtest/`(gitignore). JSON, 종목·간격별 파일. 재실행 시 네트워크를 쓰지 않는다.
- 수집은 토큰을 재발급하므로 VM이 꺼진 시간에만 실행한다(`cmd/backtest fetch`가 시작 시 경고 출력).

## 구성

- `internal/backtest/histsource.go`: `HistSource`가 `screener.Source`를 구현한다.
  - `SetClock(t)`: 시뮬레이션 시각. 이후 모든 응답은 이 시각 이전 데이터만 사용.
  - `Rankings(…, "1d", market)`: clock이 정규장 시작 전이면 전일 일봉 거래대금 순위(사전 랭킹), 장중이면 당일 정규장 시작부터
    clock까지 분봉 거래대금(거래량 × 종가) 누적 순위. `Price.LastPrice`는 clock 이전 마지막 분봉 종가.
  - `Stocks`, `StockWarnings`: 캐시.
  - `Candles`: 위 원칙 2.
- `Gate.SetClock(func() time.Time)`를 `internal/screener`에 추가한다(기본은 time.Now, 동작 불변).
- `internal/backtest/replay.go`: 거래일·시장별로 라이브 `runTradingSession` 루프를 분 단위로 재현한다.
  1. Evaluator/Gate 생성(sessionStart = 정규장 시작), `PreWarm`.
  2. 분마다: `Gate.Refresh(now)` → 활성 종목의 `setupsFor` → 그 분봉의 가격 시퀀스를 `PriceObservation`으로 만들어
     `ChaseGuard.Filter` → `ProcessTick`. 활성 순서는 라이브와 같은 랭킹 순.
  3. 분봉 안의 순서는 보수적 규칙: 포지션이 없으면 `open → high → low → close`(진입 기회를 먼저 줌),
     포지션이 있으면 `open → low → high → close`(손절을 먼저 평가). 진입 체결가는 `max(목표가, 분봉 시가)`(갭 상승이면 시가),
     손절 체결가는 `min(손절가, 분봉 시가)`(갭 하락이면 시가)로 하고, 둘 다 `SlippageBps`만큼 불리하게 보정한다.
     라이브는 폴링한 현재가로 체결하므로 이 가정이 낙관적인지 라이브 대조로 확인한다.
  4. 마감 `EOD_BUFFER`(15분) 전 강제청산, 미장은 정규장 종료 1시간 전부터 신규 진입 금지(라이브와 동일).
  5. 일별 현금은 다음 날로 이월(KR/US 공유 계좌, US는 세션 시작 환율을 고정해 달러로 운용 — 환율은 일 단위 근사로 고정값 1,350원 사용 가능).
- 비용: `simulator.Config`에 `SellTaxRate`(국내 개별주 매도세, ETF는 0), `SlippageBps`(편도)를 추가한다. 0이면 기존과 동일.
  KR 개별주/ETF 구분은 `Stocks` 응답으로 하고, 불가능하면 심볼 목록 기준으로 단순화해 한계를 문서화한다.
- 결과 출력: 거래 목록, 일별 자산, 승률/평균 수익·손실/손익분기 승률/거래당 기대값, MDD, 동일 구간 단순 보유 벤치마크
  (국장 069500, 미장 SPY 또는 상위 ETF), 비용 시나리오별(0/5/10bp) 비교.

## 검증 장치

- **누출 테스트**: 같은 날을 "전일까지의 일봉만 가진 Source"와 "전체 일봉을 가진 Source"로 돌렸을 때 목표가·추세·활성 집합이 같아야 한다.
- **라이브 대조**: 10/1~10/9 재생 결과를 `history/*.json` 실제 거래와 비교(진입 종목/시각 대체로 일치, 불일치 사유 기록).
- 단위 테스트: HistSource 시계 경계, 분봉 안 시퀀스 규칙, 비용 계산.

## 실험 (구현 후, 한 번에 하나씩)

A 손절폭을 종목 노이즈에 비례(예: k × 20일 평균 노이즈, 상한 SPEC 4.3 안에서 먼저 시험하고 범위 변경은 별도 결정) /
B 트레일링 또는 부분 익절 / C 개장 후 N분 진입 금지(0/10/20/30) / D 국장 "살 수 있는 종목 우선" 끄기, ETF 한정 /
E 노이즈 상한 4/5/6%.
구간의 앞 60%에서 조정하고 뒤 40%는 한 번만 열어 검증한다. 채택 기준은 뒤 구간에서도 거래당 기대값이 양수이고
비용 3개 시나리오에서 결론이 유지되는 것.

## 알려진 한계

생존편향(오늘 기준 상위 100개), 유의사항·종목정보는 현재 값, 국장 NXT 시간대 제외, 랭킹은 재구성(실제 API 랭킹과 다를 수 있음),
분봉 안 가격 순서는 알 수 없음(보수적 규칙으로 근사).
